# STM32 USB Status Display

**Русский** · [English](README.en.md)

Настольный индикатор на **STM32F401CCU6** и **OLED SSD1306 128×64**. Принимает данные с компьютера по USB CDC и отображает заряд мыши и наушников, состояние зарядки, время и температуру.

[![USB-индикатор на OLED](media/preview.jpg)](media/demo.mp4)

[Видео демонстрации — 23 секунды, MP4 без звука](media/demo.mp4)

## Архитектура

```text
Источники данных на ПК → Python-программа → USB CDC → STM32F401 → I2C → OLED
```

В репозитории находятся прошивка и [Python-клиент с инструкцией по запуску](python/README.md). Клиент получает заряд устройств через HID, время с ПК и температуру с wttr.in; отправляет шесть полей в формате, приведённом ниже. USB CDC создаёт виртуальный COM-порт — аппаратный UART здесь не используется.

## Возможности

- OLED по I2C1 с настройкой 400 кГц.
- Приём текстовых строк через USB Device CDC.
- Накопление строки до `\n`, игнорирование `\r` и отбрасывание переполненной строки.
- Разбор шести полей и отображение заряда, состояния зарядки, времени и температуры.
- Экран ожидания до получения данных.

## Мой вклад

Я подключил микроконтроллер и периферию, настроил проект через CubeMX и проверял работу устройства. Прошивка и программа ПК создавались **с помощью ИИ**. Проект объединяет работу с периферией микроконтроллера и получение данных на ПК.

Используются STM32 HAL, ST USB Device Library и сторонний драйвер SSD1306. Драйвер OLED не является моей разработкой; исходные сведения об авторах сохранены.

## Корпус

Я самостоятельно разработал 3D-модель корпуса OLED-индикатора в **SolidWorks** в рамках учебной работы.

## Подключения

| Узел | Конфигурация |
|---|---|
| Микроконтроллер | STM32F401CCU6 |
| OLED | SSD1306, 128×64 |
| I2C SCL / SDA | PB6 / PB7 |
| USB D− / D+ | PA11 / PA12 |

Таблица отражает конфигурацию прошивки. Точные модели платы и OLED-модуля, питание и внешние подтяжки пока не задокументированы.

## Формат данных

Пример строки, соответствующий разбору в прошивке:

```text
L75 LC0 A60 AC1 T14:30 W18
```

После последнего поля передать символ `\n`.

| Поле | Значение |
|---|---|
| `L` / `A` | Проценты заряда мыши / наушников |
| `LC` / `AC` | Заряжается: 1 — да, 0 — нет, −1 — неизвестно |
| `T` | Строка времени, например `14:30` |
| `W` | Температура, например `18` |

Прошивка использует специальные значения: нулевой заряд отображается как `--%`, отрицательное значение заряда наушников — как `USE AUD HQ`. Это условности текущего интерфейса. Валидатор диапазонов входных значений не реализован полностью.

## Сборка

**Arm Compiler 6.22**, **Keil.STM32F4xx_DFP 3.1.1**. Пакет в `.ioc`: **STM32Cube FW_F4 V1.28.3**.

1. Клонировать репозиторий, сохранив структуру каталогов.
2. Открыть `MDK-ARM/power.uvprojx` в Keil µVision с указанным компилятором и device pack.
3. Выполнить **Rebuild**. Перегенерация CubeMX не нужна для сборки сохранённого проекта.

Результаты сборки попадают в `MDK-ARM/power/` и исключены из Git. Включена необходимая часть зависимостей текущего проекта; для перегенерации/расширения конфигурации потребуется соответствующий пакет CubeMX.

## Где читать код

- `Core/Src/main.c` — разбор полей и отрисовка экрана.
- `USB_DEVICE/App/usbd_cdc_if.c` — накопление входных строк.
- `Core/Src/ssd1306.c`, `Core/Inc/ssd1306.h`, файлы `fonts` — сторонний драйвер и шрифты.
- `power.ioc` — настройка периферии.
- `python/maxwell_battery.py` — получение данных на ПК и отправка через USB CDC.

## Демонстрация и ограничения

Видео показывает запуск, ожидание и затем вывод заряда мыши 44%, наушников 26%, времени и температуры. На ПК также показано 44% для PRO X SUPERLIGHT 2.

- Python-клиент рассчитан на Audeze Maxwell и Logitech G PRO X Superlight 2. Инструкция и границы проверки — в [python/README.md](python/README.md).
- Основной цикл и обработчик USB используют общий буфер и флаг; возможные потери/смешивание данных при частых сообщениях ещё не проверены. `volatile` у флага не заменяет синхронизацию.
- Поведение при отключении USB, повреждённых данных и выходе показаний за диапазон требует дальнейшей проверки.

Результат проверки сборки описан в [VALIDATION.md](VALIDATION.md).
